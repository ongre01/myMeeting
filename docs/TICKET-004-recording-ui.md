# TICKET-004 녹음 화면과 상태 표시 구현

## 구현 범위

- 메인 창에 회의 제목, 마이크 선택, 장치 목록 새로 고침, 녹음 시작/종료 버튼을 추가했다.
- 대기, 녹음 중, 녹음 종료 중, 녹음 완료, 오류 상태를 화면과 상태 표시줄에 보여 준다.
- `QElapsedTimer`와 250 ms 주기의 `QTimer`로 녹음 경과 시간을 `hh:mm:ss` 형식으로 표시한다.
- 녹음 시작 시 `MeetingStorage`가 실행 파일의 `meetings` 폴더 아래에 회의별 디렉터리를 만들고, `AudioRecorder`가 그 안의 `meeting.wav`에 녹음한다.
- 회의 제목은 기존 `MeetingStorage` 규칙에 따라 폴더명에 반영된다.
- `QMediaDevices::audioInputsChanged` 신호와 새로 고침 버튼이 현재 입력 장치 목록을 다시 읽는다.
- 음성은 선택한 로컬 마이크에서 로컬 WAV 파일로만 저장하며, 네트워크나 외부 AI API를 사용하지 않는다.

일시정지·재개는 이 티켓의 Implementation Scope에 포함된 시작/종료보다 넓은 기능이므로 추가하지 않았다.

## 상태와 버튼 규칙

| 상태 | 시작 | 종료 | 제목/장치/새로 고침 |
|---|---:|---:|---:|
| 대기, 녹음 완료, 시작 실패 | 장치가 있으면 활성 | 비활성 | 활성 |
| 녹음 중 | 비활성 | 활성 | 비활성 |
| 녹음 종료 요청 중 | 비활성 | 비활성 | 비활성 |
| 마이크 없음 | 비활성 | 비활성 | 제목과 새로 고침만 활성 |

녹음 중에는 UI에서 시작 버튼을 비활성화하고, 시작 슬롯에서도 `AudioRecorder::isRecording()`을 다시 확인해 중복 시작을 차단한다.

## 오류와 경계 조건

- 장치가 없으면 콤보 박스에 “사용 가능한 마이크 없음”을 표시하고 시작을 비활성화한다.
- 선택한 장치가 시작 직전에 사라지면 장치 목록을 새로 고침하라는 오류를 표시한다.
- 저장 폴더 생성이나 WAV 시작이 실패하면 사용자용 오류를 표시하고 다시 시작할 수 있는 대기 버튼 상태로 복귀한다.
- 실제 녹음이 시작되기 전에 실패한 경우, 해당 시도에서 만든 빈 WAV와 빈 회의 폴더를 정리한다. 녹음 중 오류가 나면 복구 가능한 부분 WAV를 삭제하지 않는다.
- 시작 실패 후에는 장치 선택과 시작 버튼을 다시 활성화해 재시도할 수 있다.

## `AudioRecorder` UI 연결 API

`inputDevices()`는 UI가 보관할 장치 ID와 사용자에게 보여 줄 설명을 반환한다. `startRecording(deviceId, filePath)`는 시작 시점의 장치 목록에서 ID를 다시 확인하고 기존 `QAudioDevice` 기반 녹음 로직으로 연결한다.

```cpp
const QList<AudioRecorder::InputDeviceInfo> devices = recorder.inputDevices();
if (!devices.isEmpty()) {
    recorder.startRecording(devices.first().id, meetingPaths.wav);
}
```

## 자동 검증

`tests/tst_appshell.cpp`의 가짜 로컬 레코더는 물리 마이크를 켜지 않고 UI와 저장 흐름을 검증한다.

- 장치 목록, 초기 대기 상태, 0초 경과 시간, 버튼 활성 상태
- 마이크가 없을 때의 안내 문구와 장치/시작 컨트롤 비활성화
- 제목 입력 후 시작/종료 버튼으로 44-byte의 유효한 0초 RIFF/WAVE 생성
- 녹음 중 경과 시간 증가
- 버튼 비활성화와 슬롯 방어 로직의 중복 시작 차단
- 첫 시작 실패 후 오류 표시, 빈 폴더 정리, 두 번째 시작 성공
- 기존 회의 저장소, WAV 포맷, 장치 미선택 오류 회귀 검증

Windows 11, Qt 6.11.0 MSVC 2022 64-bit 환경에서 앱과 테스트의 Debug/Release 빌드가 성공했고, Debug/Release에서 각각 Qt Test 16건이 실패 및 건너뜀 없이 통과했다. Debug/Release 앱 프로세스가 즉시 종료하지 않고 이벤트 루프에 진입하는 것도 확인했다.

## 실제 마이크 수동 확인

자동 테스트는 사용자 동의 없이 물리 마이크를 켜지 않는다. 실제 장치는 다음 순서로 별도 확인한다.

1. 회의 제목을 입력하고 사용할 마이크를 선택한다.
2. “녹음 시작”을 누른 뒤 상태가 “녹음 중”으로 바뀌고 경과 시간이 증가하는지 확인한다.
3. 짧게 말한 뒤 “녹음 종료”를 누른다.
4. 실행 파일 위치의 `meetings/<timestamp>_<title>/meeting.wav`를 재생해 음성이 들리는지 확인한다.
5. 녹음 중 시작 버튼이 비활성화되는지, 마이크를 비활성화한 후 오류가 표시되고 다시 시작할 수 있는지 확인한다.
